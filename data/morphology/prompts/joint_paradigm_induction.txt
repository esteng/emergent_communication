You are a field linguist jointly inducing MORPHEME BOUNDARIES, SUBSTITUTION CLASSES, and CONSTRUCTION TEMPLATES from a complete emergent codebook. These are one inference problem: NEVER posit a boundary first and invent classes for it afterward. A split is valid only when its parts make a compositional, meaning-consistent multi-entry paradigm.

Partition every supplied symbol into either lexical_symbols or entries, exactly once. A lexical symbol is an opaque stored label and receives no segmentation. It is entirely acceptable for the whole run to be a flat_lexicon, with all symbols lexical and classes/constructions/entries empty. Prefer this over false morphology.

EVIDENCE REQUIRED FOR A PARADIGM: (1) at least one slot shows a substitution contrast — two or more fillers alternating in the same frame (a minimal pair); (2) recurring forms make stable semantic contributions; (3) contrasting fillers express corresponding meaning contrasts in the same frame; and (4) each whole meaning is predictable from the proposed parts. Shared characters, position, or numbering alone are not evidence. Do not create a generic ROOT, STEM, NUMBER, or MISC class merely to absorb residues. Lexical action roots may share a functional class only when they truly contrast inside the same productive frame.

Use the supplied NEGOTIATION EVIDENCE to distinguish a declared schema from parallel mnemonic abbreviations. An enumerated list such as `T6=tone all six; TO=tone opposite; FAN2=fan two; FAN6=fan six` defines whole action tokens; the parallel English expansions alone do NOT license internal morphemes. A two-item paradigm is justified only when the agents explicitly pair the contrast (for example `Ld/Lb=dim/bright lamp`), explicitly define the reusable components, or demonstrably recombine those components outside a memorized list. Do not infer a paradigm solely from initials or digits that make separately listed abbreviations look retrospectively decomposable.

OPTIONAL (NULLABLE) SLOTS — PREFER ONE CONSTRUCTION WITH OPTIONAL SLOTS OVER SEVERAL FIXED-DEPTH ONES. Codes of different lengths that share the same ordered classes are the SAME construction: give it a single template equal to the fullest attested path, and let shorter codes omit optional slots (their class path is a subsequence of that template). Do NOT split a family into a two-slot and a three-slot construction merely because some codes carry an extra optional slot. A construction need NOT be attested at full depth by many entries: a single maximal code together with shorter codes that each fill a subsequence of its classes is sufficient evidence for the optional slots — support lives at the slot/class level (does the slot substitute?), not at the whole-construction level. Reuse the SAME class_id across constructions whenever a filler plays the same role, so nested and related templates share their classes rather than duplicating them.

OPAQUE INDEX TEST: families such as P1, P2, ... are NOT P + NUMBER when 1, 2, etc. merely select unrelated stored procedures. The numeral must contribute its literal quantity/count/duration meaning to the whole code. Thus P1='procedure A' and P2='unrelated procedure B' remain whole lexemes. In contrast x3='repeat three times' and x5='repeat five times' support OPERATOR + COUNT. Apply the same test to every repeated prefix/suffix and every digit.

CLASSES ARE PARADIGMATIC: fillers in one class must be mutually substitutable in a shared morphotactic frame and make the same kind of contribution. Different semantic values are normal alternants (dim/bright in a MODIFIER class), but different semantic roles are not. Do not merge all first or final pieces across unrelated constructions. Codes differing only by an optional class share one construction whose class_sequence is the fullest licensed path. Use the smallest defensible set of construction families.

HOMOGRAPHY DOES NOT BLOCK A PARADIGM. A standalone symbol may have an unrelated lexical meaning while the same surface substring is a morpheme inside a supported construction. In particular, Ld='dim lamp' and Lb='bright lamp' are a decisive minimal pair: analyze L as LAMP and {d,b} as a MODIFIER class even if standalone L elsewhere means 'left face'. Two entries are sufficient when they form such an exact compositional contrast. Judge each occurrence from its local meaning and frame rather than allowing an unrelated whole-code homograph to veto it.

PARADIGM DECLARATIONS (STANDALONE KEY ENTRIES). The codebook often DECLARES a class's full value set as standalone single-morpheme key entries, e.g. 'g = gentle intensity', 'm = moderate intensity', 'f = firm intensity', or 'N = front face', 'S = back face', 'U = up face'. These are authoritative evidence of a substitution class's membership EVEN WHEN a value rarely or never appears inside a multi-morpheme code. When a set of standalone entries share one semantic dimension and match a class you posit, list EVERY member in that class's declared_fillers, giving each the surface form it takes INSIDE codes (bare 'g' for a suffix; bracketed '[N]' when the class is written bracketed) and its gloss. declared_fillers complements the fillers observed in entries and does not remove those symbols from lexical_symbols; leave it empty for a class with no such standalone key. This recovers full paradigms (all intensities, all faces) that pure co-occurrence would miss.

COMPOSITIONAL GLOSSES. Every morpheme gloss must state ONLY that morpheme's own contribution, so the whole code's meaning is recoverable by concatenating its parts. An action/procedure root glosses as the bare action it denotes ('fan', 'cool cloth', 'board', 'bell at each edge') and MUST NOT restate the face, duration, count, or intensity that other slots supply — never 'fan on the specified face for the given seconds, gentle'. A face morpheme glosses as just the face ('front face'); a duration as just the duration; an intensity as just the intensity. If a gloss already contains another slot's contribution it is not compositional and is wrong. Keep this discipline in both entry morphemes and declared_fillers.

Assign exactly one content head with head_morpheme_index. Every entry's class path must be an order-preserving subsequence of its declared construction template. A repeated class requires repeatable=true. Do not include lexical symbols in entries, classes, or constructions.
